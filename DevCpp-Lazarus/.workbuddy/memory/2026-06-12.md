# 2026-06-12 工作日志

## BrowserView 垂直间距修复（第二轮）
- **现象**：上一轮 LoadColor 字体修复后，鼠标移入字体大小已保持，但各分支垂直间距仍变小
- **用户分析**：根因在 `BrowserViewAdvancedCustomDrawItem` 中 `cdPrePaint` 阶段设置的 `Sender.Canvas.Font.size` 只影响绘制画布，不影响 TTreeView 的 item 高度计算。TreeView item 高度由控件自身 Font 属性决定
- **修复**（`main.pas`）：
  - 新增 `BrowserViewAdvancedCustomDraw` 树级事件声明和实现
  - `cdPrePaint` 阶段：`Sender.Canvas.Font.Assign(Sender.Font)` 同步画布字体，计算 `ItemH := Abs(Font.Height) + 6`（字体像素高 + 6px 上下边距），设 `DefaultItemHeight := ItemH`
  - 用 `DefaultItemHeight <> ItemH` 守卫防止设置 item 高度触发递归重绘
  - 注册事件：`BrowserView.OnAdvancedCustomDraw := @BrowserViewAdvancedCustomDraw`

## BrowserView 垂直间距修复（第三轮）— 最终根因
- **根因**：LFM 中 `BrowserView.Options` 包含 `tvoAutoItemHeight`。LCL 源码 `treeview.inc:4727` 中 `SetDefaultItemHeight` 在 `tvoAutoItemHeight` 启用时直接 `exit`（除 `csLoading` 阶段外）。前两轮在 `LoadColor` 和 `OnAdvancedCustomDraw` 中设置的 `DefaultItemHeight` **都未生效**
- **修复**：
  1. **LFM**：从 `BrowserView.Options` 中移除 `tvoAutoItemHeight`
  2. **LoadColor**：设完 Font 后直接设 `BrowserView.DefaultItemHeight := Abs(BrowserView.Font.Height) + 6`
  3. **BrowserViewAdvancedCustomDraw** 树级事件保留（作为运行时一致性检查）
- **涉及文件**：`main.lfm` (L197)、`main.pas` (L1755, L8558)

## CompilerOutput 选中行字体颜色变黑修复
- **现象**：错误（红）、警告（紫）、提示（深蓝）在选中时都变成黑色
- **根因**：Win32 主题渲染（comctl32 v6）选中 item 时忽略 `clrText`，强制用主题高亮色画文字
- **尝试1**：`DefaultDraw := False` + 完全手动绘制 → 深蓝背景、乱码、点击无效。**已回滚**
- **尝试2**：`cdPostPaint` + `bsClear` 透明重绘 → 文字重影。**已回滚**
- **尝试3**：`cdPostPaint` + `FillRect(clHighlight)` 擦除后重绘 → 仍然深蓝背景、乱码、点击无效。**已回滚**
- **最终方案**：在 `CompilerOutputAdvancedCustomDraw` 树级事件中调用 `SetWindowTheme(Handle, '', '')` 禁用该 ListView 的视觉主题
  - 经典渲染尊重 `clrText`，`Canvas.Font.Color` 设置对选中行生效
  - 用 `Tag=0` 作为一次性标志，避免重复调用 `SetWindowTheme`
  - `AdvancedCustomDrawItem` 代码无需任何修改
  - `uses` 添加 `UxTheme` 单元
  - 视觉影响：选中行高亮为纯色矩形（无渐变），对编译输出窗口可接受
